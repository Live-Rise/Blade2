## Blade2 0.9.0.4

内核引导链重做的一版：冷启 ~6.6s 的模块装载风暴可以整段跳过——**退出保活常驻内核，下次启动探活直连**，暖启降到 ~0.6s。本次另修掉「关于」页内核加载行永远停在 83% 的记分板 bug。

### 内核常驻复用

退出时内核保活，状态文件记 `pid / url / 版本 / exe 路径 / 时间`；下次启动先探活，命中就直接 attach，不再重新 spawn 内核。版本不符、pid 已死、pid 被复用、探活失败四条路各自回收后回退冷启，不会挂在一个坏的半成品上。

- 冷启后产物同样登记常驻，所以**第一次 cold、之后每次 warm**
- 异常退出残留的内核会被清扫掉（只认父进程链上没有活 Blade² 的本安装内核，不碰机器上别的 node）；常驻内核在清扫眼里是"孤儿"，靠 `sparePid` 豁免，重试走 `KillAndClear` 硬收
- 状态文件五键与 Rust 侧实现互通，两边切换不会互相踩
- 内核 bundle 升到 `0.2.1-rc.3`（官方树零补丁，diff 校验逐字节一致）

### 修：内核加载停在 83%

「关于」页那行百分比不是真实进度条，是 **已完成里程碑数 / 6**：默认插件就绪 → 认证完成 → 事件通道就绪 → 工作区清单就绪 → 会话与模型就绪 → 引导完成。

复用常驻内核那条分支把插件修补挪进了后台 `Task.Run`，**顺手把第一条里程碑一起漏了**——6 段只落地 5 段，`5/6 = 83.33%` 取整 83%。因为常驻复用是常态，所以除首启外每次启动都停在 83%，而日志里 `引导完成` 早已落地：链路跑完了，只是记分板少记一段。

修法：进入 attach 分支即记「默认插件就绪」（常驻内核的插件早已装载完，如实；后台只做幂等修补）。放在 `Task.Run` 之后补记会让历史行乱序——末段都落地了才补第一段。

### 安装

包是自签名的，**别的机器装之前先信任证书**，否则会报 `0x800B010A`：

```powershell
CertUtil -addstore TrustedPeople Blade2.cer
Add-AppxPackage Blade2_0.9.0.4_x64.msix
```

从 0.9.0.3 及更早版本升上来直接装即可。**同版本号覆盖安装会被 `0x80073CFB` 挡**（包标识相同而内容不同，系统防篡改，`-ForceUpdateFromAnyVersion` 也绕不过），需要先卸再装：

```powershell
Remove-AppxPackage (Get-AppxPackage Blade2).PackageFullName
Add-AppxPackage Blade2_0.9.0.4_x64.msix
```

用户数据在包外（`%LOCALAPPDATA%\Blade2`），卸载重装不受影响；容器内仅 `ui-language` 会随卸载重置回默认中文。
